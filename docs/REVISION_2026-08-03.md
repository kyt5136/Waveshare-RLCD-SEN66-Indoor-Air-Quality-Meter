# Maintenance, Resilience, and On-Device Settings Revision

This revision extends the 2026-07-29 firmware release. It keeps the SEN66 as
the primary indoor-air sensor. The board's onboard SHTC3 is a diagnostic and
low-power fallback source only; it does not replace the SEN66's CO2, VOC, NOx,
or particulate measurements.

## What changed

| Area | Implemented behavior |
|---|---|
| Sensor confidence | Starts with an I2C diagnostic scan, reads the SHTC3 with CRC validation, compares paired SEN66/SHTC3 temperature and humidity samples, and records results in FATFS. |
| Low-power continuity | Retains six-hour history in FATFS and can use a qualified, corrected SHTC3 temperature/humidity value while the SEN66 duty cycle is stopped. |
| Particulate quality | Ignores non-finite PM frames, suppresses AQI for the first 10 seconds after an SEN66 start or clean-out, then applies an EMA with alpha 0.35 before calculating indoor AQI. Raw PM remains visible. |
| Maintenance | Adds an on-device settings page for a five-minute Wi-Fi window, the CO2 workflow, and an SEN66 fan clean-out. |
| Power and display | Uses an asserted USB-host connection as the external-power signal, gives button interaction a 60-second high-refresh window, and reads the RTC at 5 Hz instead of every loop. |
| Weather urgency | Adds the OpenWeather 15-minute timeline alongside the 1-minute and air-pollution requests. New rain or severe-weather events can show the 60-minute page once. |
| Presentation | Standardizes page headers and several layouts; page count is now 15. |

## I2C scan and sensor comparison

At startup the firmware scans GPIO 13/14 and labels the expected responders:
ES8311 at `0x18`, ES7210 at `0x40`, PCF85063A at `0x51`, SEN66 at `0x6B`, and
SHTC3 at `0x70`. Other responding addresses are reported as unknown; an
expected address missing from the scan is reported separately. This is a
diagnostic aid, not proof that every device is operating correctly.

The SHTC3 is awakened, measured in high-precision mode, CRC-checked, and put
back to sleep for each approximately 15-second sample. Paired samples are
logged to `/sensor_compare.csv` on the configured FATFS partition. The file is
rotated to `/sensor_compare.old.csv` when it exceeds 4 MiB.

The firmware collects at least 100 valid pairs over at least 12 hours before
marking the comparison as qualified. It then keeps a bounded, slowly adapting
mean and variance of the SEN66-minus-SHTC3 temperature and humidity deltas.
Only a qualified comparison is applied to the SHTC3 fallback. It is not a
calibration certificate and does not modify the SEN66.

## Persistent history

The 24-point, 15-minute temperature/humidity history is serialized to
`/history.csv`. On boot, samples older than six hours are discarded. The code
first mounts FATFS without formatting; if that fails it attempts to format the
configured FATFS partition and mount it again. That recovery path can erase
existing FATFS data, so it is intended for a dedicated device partition rather
than shared user files.

## PM warm-up, AQI, and fan clean-out

AQI is unavailable (`--`) until the 10-second PM gate opens. This prevents the
first particle frames after a measurement restart, and the dust released after
a clean-out, from changing the displayed indoor AQI. Once warm, PM2.5 and PM10
are independently exponentially smoothed before the existing EPA breakpoint
calculation. The displayed AQI remains the higher sub-index.

The settings-page **SEN66 fan clean-out** action requests the Sensirion fan
cleaning command and keeps the station awake for its approximately 12-second
completion window. Completion reopens the PM warm-up gate. It is maintenance,
not a substitute for keeping the inlet/outlet clear or for using a reference
instrument.

## Page 14: Settings

The new page is enabled by default and is appended without renumbering prior
pages. Existing NVS page masks are migrated to schema 3 and gain the page-14
bit. On this page:

- Hold **BOOT** (GPIO 0) to move the selection.
- Tap **KEY** (GPIO 18) to apply the selected action.
- Hold **KEY** to advance to the next page.
- Tap **BOOT** to go to the previous page.

The actions are a five-minute Wi-Fi/web-interface window, the guarded CO2
calibration workflow, and the fan clean-out. The on-device calibration action
may proceed offline without downloaded pressure compensation; use the web
workflow when fresh WeatherAPI pressure is available and required.

## Power, network, and alerts

`Serial.isPlugged()` is used only when the selected Arduino USB configuration
exposes it. Its debounced host-connection state selects external-power mode;
battery voltage is deliberately not used to infer USB power. External-power
mode keeps the display interactive and uses a ten-minute online refresh
interval. Low-power mode retains the existing 30-minute interval unless a rain
event requests the ten-minute update window.

OpenWeather requests now include the One Call 15-minute timeline. A newly
observed chance of rain or a changed non-empty alert identifier can navigate
once to the 60-minute page if that page is included in navigation. This is an
attention cue, not an emergency-alert delivery system.

## Verification scope

Static whitespace validation (`git diff --check`) passed. Arduino CLI 1.5.1
compiled the sketch with Arduino-ESP32 3.3.11 and the documented library
versions using `esp32:esp32:esp32s3:FlashSize=16M,PartitionScheme=app3M_fat9M_16MB,PSRAM=opi`.
The result used 1,407,385 bytes (44%) of the 3 MB application partition and
52,944 bytes (16%) of dynamic memory. Hardware verification still needs the
acceptance checks in [Operations](OPERATIONS.md).
